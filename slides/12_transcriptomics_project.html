12차시: 미니 프로젝트 — 전사체 형태의 데이터 분석

R 기초 프로그래밍

오늘의 학습 목표

  1. 메타데이터와 유전자 발현 데이터를 불러와 구조와 품질을 점검할 수 있다.
  2. 샘플 순서를 검증하고 QC 조건에 맞는 샘플을 선택할 수 있다.
  3. 실험 조건별 유전자 발현을 요약하고 기본 그래프로 표현할 수 있다.
  4. 분석 결과와 설정값을 CSV, PNG, RDS 파일로 정리할 수 있다.

지금까지 배운 내용을 연결한다

단계 사용하는 내용
데이터 불러오기 상대 경로, read.csv()
품질 점검 str(), summary(), is.na(), duplicated()
샘플 선택 비교·논리 연산자, 데이터 프레임 인덱싱
계산 함수, 벡터화 연산, 그룹별 요약
시각화 막대그래프, 상자그림, 산점도
결과 정리 리스트, CSV, PNG, RDS

프로젝트 질문

이 프로젝트에서는 다음 질문에 답합니다.

  1. 분석 기준을 만족하는 샘플은 무엇인가?
  2. control과 treated에 분석 가능한 샘플이 각각 몇 개 있는가?
  3. 각 유전자의 조건별 평균 발현량은 얼마인가?
  4. 조건 간 평균 발현 차이가 큰 유전자는 무엇인가?

사용하는 데이터

data/
├─ sample_metadata.csv
└─ gene_expression.csv
  • sample_metadata.csv: 샘플별 조건과 QC 지표
  • gene_expression.csv: 유전자별 샘플 발현량
  • 두 파일 모두 수업용으로 만든 합성 데이터입니다.

샘플 메타데이터의 구조

행 의미
한 행 한 샘플

주요 열:

  • sample_id, condition, batch
  • cell_count, median_genes, mito_percent
  • doublet_rate, passed_qc

유전자 발현표의 구조

gene_id,control_1,control_2,...,treated_3
MS4A1,52,48,...,24
CD3D,18,20,...,64
  • 한 행은 유전자 하나입니다.
  • gene_id를 제외한 각 열은 샘플 하나입니다.
  • 각 셀에는 교육용 발현량이 들어 있습니다.

프로젝트 분석 흐름

1. 파일 확인 및 불러오기
2. 구조·결측값·중복 점검
3. 두 파일의 샘플 정렬 검증
4. QC 조건 생성 및 샘플 선택
5. 조건별 평균 발현 계산
6. 요약표와 그래프 작성
7. 결과 저장 및 읽기 검증

각 단계의 결과를 확인한 뒤 다음 단계로 이동합니다.

1단계: 입력 파일 경로를 지정한다

metadata_path <- "data/sample_metadata.csv"
expression_path <- "data/gene_expression.csv"

file.exists(metadata_path)
file.exists(expression_path)

두 결과가 모두 TRUE인지 확인합니다.

두 CSV 파일을 불러온다

sample_metadata <- read.csv(metadata_path)
gene_expression <- read.csv(
  expression_path,
  check.names = FALSE
)

check.names = FALSE는 CSV에 기록된 샘플 열 이름을 그대로 유지합니다.

불러온 직후 일부 행을 확인한다

head(sample_metadata)
head(gene_expression)

확인할 사항:

  • 예상한 파일이 맞는가?
  • 첫 행이 열 이름으로 처리됐는가?
  • 값이 여러 열로 올바르게 나뉘었는가?

2단계: 데이터 크기를 확인한다

dim(sample_metadata)
dim(gene_expression)
  • 메타데이터 행 수는 샘플 수입니다.
  • 발현표 행 수는 유전자 수입니다.
  • 발현표 열 수는 gene_id 열과 샘플 열을 합한 수입니다.

열 이름과 자료형을 확인한다

names(sample_metadata)
names(gene_expression)

str(sample_metadata)
str(gene_expression)

발현량 열이 숫자형으로 불러와졌는지 확인합니다.

결측값 개수를 확인한다

colSums(is.na(sample_metadata))
colSums(is.na(gene_expression))
  • 메타데이터의 doublet_rate에는 의도적인 결측값이 하나 있습니다.
  • 발현표에는 결측값이 없어야 합니다.

중복 식별자를 확인한다

any(duplicated(sample_metadata$sample_id))
any(duplicated(gene_expression$gene_id))

샘플 ID와 유전자 ID는 각각 고유해야 합니다.

숫자형 값의 범위를 확인한다

summary(sample_metadata)
summary(gene_expression[, -1])

음수 발현량이나 예상 밖의 QC 값이 없는지 살펴봅니다.

3단계: 두 파일의 샘플 이름을 추출한다

metadata_sample_ids <- sample_metadata$sample_id
expression_sample_ids <- names(gene_expression)[-1]

metadata_sample_ids
expression_sample_ids

-1은 첫 번째 gene_id 열을 제외합니다.

샘플 이름과 순서가 모두 같은지 확인한다

identical(metadata_sample_ids, expression_sample_ids)

TRUE여야 각 샘플의 메타데이터와 발현량이 같은 순서로 대응합니다.

이름 집합만 같아도 순서가 다르면 잘못된 샘플끼리 연결될 수 있습니다.

샘플 정렬 검증은 분석 전에 수행한다

stopifnot(
  identical(metadata_sample_ids, expression_sample_ids)
)
  • 조건이 TRUE이면 분석을 계속합니다.
  • FALSE이면 실행을 중단하고 두 파일의 이름과 순서를 수정합니다.

4단계: QC 기준을 명시한다

qc_parameters <- list(
  min_cells = 1200,
  min_genes = 2000,
  max_mito = 8,
  max_doublet = 4
)

설정값을 리스트에 모으면 어떤 기준을 사용했는지 기록하기 쉽습니다.

이 수치는 R 프로젝트 연습을 위한 예시이며 실제 분석 기준이 아닙니다.

결측값이 없는 doublet 조건을 만든다

known_doublet_rate <-
  !is.na(sample_metadata$doublet_rate)

low_doublet_rate <-
  sample_metadata$doublet_rate <= qc_parameters$max_doublet

결측값을 먼저 확인하고 기준과 비교합니다.

모든 QC 조건을 결합한다

qc_condition <-
  sample_metadata$passed_qc &
  sample_metadata$cell_count >= qc_parameters$min_cells &
  sample_metadata$median_genes >= qc_parameters$min_genes &
  sample_metadata$mito_percent < qc_parameters$max_mito &
  known_doublet_rate &
  low_doublet_rate

각 행에 대해 모든 조건이 참이어야 TRUE입니다.

QC 결과를 메타데이터에 추가한다

sample_metadata$qc_result <- qc_condition
sample_metadata$qc_label <- ifelse(
  qc_condition,
  "pass",
  "review"
)

sample_metadata[, c("sample_id", "condition", "qc_label")]

원본 QC 지표와 새 판정 결과를 함께 확인합니다.

QC 통과 샘플을 선택한다

analysis_metadata <- sample_metadata[qc_condition, ]
analysis_metadata
analysis_sample_ids <- analysis_metadata$sample_id
analysis_sample_ids

선택 결과의 행 수와 샘플 이름을 확인합니다.

조건별 분석 샘플 수를 확인한다

analysis_condition_counts <- table(
  analysis_metadata$condition
)

analysis_condition_counts

두 조건에 분석 가능한 샘플이 있는지 확인합니다.

발현표에서도 같은 샘플 열을 선택한다

analysis_expression <- gene_expression[, c(
  "gene_id",
  analysis_sample_ids
)]

analysis_expression

메타데이터에서 통과한 샘플 ID를 발현표의 열 이름으로 사용합니다.

선택한 두 객체의 대응을 다시 확인한다

identical(
  analysis_metadata$sample_id,
  names(analysis_expression)[-1]
)

필터링 이후에도 샘플 이름과 순서가 같아야 합니다.

5단계: 조건별 샘플 ID를 만든다

control_ids <- analysis_metadata$sample_id[
  analysis_metadata$condition == "control"
]

treated_ids <- analysis_metadata$sample_id[
  analysis_metadata$condition == "treated"
]

각 조건에 해당하는 발현표 열 이름을 얻습니다.

조건별 발현값을 선택한다

control_expression <- analysis_expression[
  , control_ids, drop = FALSE
]

treated_expression <- analysis_expression[
  , treated_ids, drop = FALSE
]

drop = FALSE는 샘플이 하나뿐이어도 데이터 프레임 형태를 유지합니다.

rowMeans()로 유전자별 평균을 계산한다

control_mean <- rowMeans(control_expression)
treated_mean <- rowMeans(treated_expression)
  • 각 행은 유전자 하나입니다.
  • rowMeans()는 행마다 여러 샘플 값의 평균을 계산합니다.

유전자별 요약표를 만든다

gene_summary <- data.frame(
  gene_id = analysis_expression$gene_id,
  control_mean = control_mean,
  treated_mean = treated_mean
)

gene_summary

한 행에 한 유전자의 조건별 평균을 정리합니다.

조건 간 평균 차이를 계산한다

gene_summary$difference <-
  gene_summary$treated_mean - gene_summary$control_mean

gene_summary
  • 양수: treated 평균이 더 큼
  • 음수: control 평균이 더 큼
  • 이 값만으로 통계적 유의성이나 생물학적 중요성을 판단할 수는 없습니다.

절댓값 차이가 큰 순서로 정렬한다

gene_order <- order(
  abs(gene_summary$difference),
  decreasing = TRUE
)

gene_summary_sorted <- gene_summary[gene_order, ]
gene_summary_sorted

order()는 값을 정렬할 행 위치를 반환합니다.

이 프로젝트의 발현 비교 한계

  • 교육용 합성 데이터입니다.
  • 샘플 수와 유전자 수가 매우 적습니다.
  • 정규화, 배치 보정, 분산 추정, 통계 검정을 수행하지 않았습니다.
  • 평균 차이는 실제 차등 발현 분석 결과가 아닙니다.

이 프로젝트의 목적은 R 분석 흐름을 연결하는 것입니다.

selected_gene <- "CD3D"

그래프 제목에 유전자 이름을 포함합니다.

7단계: 결과 폴더를 준비한다

dir.create("results", showWarnings = FALSE)

원본 데이터가 있는 data/와 분석 결과가 있는 results/를 분리합니다.

메타데이터와 유전자 요약표를 저장한다

write.csv(

  row.names = FALSE

write.csv(
  gene_summary_sorted,
  "results/project_gene_summary.csv",
  row.names = FALSE
)

CSV는 사람이 확인하고 다른 프로그램과 공유하기 쉽습니다.

그래프를 PNG로 저장한다

png(

barplot(

분석 전체를 리스트로 정리한다

project_result <- list(
  metadata = analysis_metadata,
  expression = analysis_expression,
  gene_summary = gene_summary_sorted,
  parameters = qc_parameters
)

입력에서 선택된 데이터, 요약 결과, 사용 기준을 하나의 객체에 묶습니다.

프로젝트 객체를 RDS로 저장한다

saveRDS(
  project_result,
  "results/transcriptomics_project.rds"
)

RDS는 리스트 내부의 데이터 프레임과 설정값 구조를 보존합니다.

저장 결과를 다시 읽어 검증한다

restored_project <- readRDS(
  "results/transcriptomics_project.rds"
)

identical(project_result, restored_project)
str(restored_project, max.level = 2)

CSV와 PNG 파일도 실제로 열어 내용을 확인합니다.

재현 가능한 프로젝트가 갖춰야 할 것

  • 입력 파일의 위치와 의미
  • 데이터 구조 및 품질 점검 코드
  • 선택 기준과 결측값 처리 방법
  • 요약과 그래프를 만드는 코드
  • 결과 파일과 실행 환경 정보
  • 결과의 한계와 해석 범위

결과를 설명할 때 과정과 한계를 함께 말한다

예시:

교육용 QC 기준을 적용해 분석 샘플을 선택하고, 조건별 유전자 평균 발현량을 계산했다. 이 데이터는 합성 자료이고 표본 수가 적으며 정규화와 통계 검정을 수행하지 않았으므로 실제 차등 발현 결과로 해석할 수 없다.

프로젝트 점검표

  1. 입력 파일이 존재하는가?
  2. 식별자에 결측값이나 중복이 없는가?
  3. 메타데이터와 발현표의 샘플 이름 및 순서가 같은가?
  4. QC 기준과 결측값 처리 방법이 코드에 기록됐는가?
  5. 필터링 후 두 조건에 샘플이 남아 있는가?
  6. CSV, PNG, RDS 결과를 다시 열어 확인했는가?

오늘 완성한 분석 흐름

불러오기 → 검증 → QC → 샘플 선택 →
조건별 발현 요약 → 시각화 → 저장 → 복원 검증

이 흐름은 실제 Seurat 분석에서도 입력과 함수는 달라지지만 기본 사고 과정으로 이어집니다.

과정 전체 정리

  • R 객체와 기본 자료형을 확인했습니다.
  • 벡터, 행렬, 데이터 프레임, 리스트를 사용했습니다.
  • 조건식, 반복, 함수로 분석 작업을 표현했습니다.
  • 데이터를 요약하고 그래프로 전달했습니다.
  • 상대 경로와 검증 단계를 사용해 재현 가능한 결과를 만들었습니다.

종료 점검

  1. 두 파일의 샘플 순서를 왜 확인해야 합니까?
  2. QC 기준을 리스트에 저장하면 어떤 점이 좋습니까?
  3. rowMeans()는 발현표의 어느 방향으로 계산합니까?
