6차시: 데이터 불러오기와 저장하기

R 기초 프로그래밍

오늘의 학습 목표

  1. CSV 파일을 데이터 프레임으로 불러올 수 있다.
  2. 불러온 데이터의 구조와 이상 여부를 확인할 수 있다.
  3. 프로젝트 루트 기준의 상대 경로를 사용할 수 있다.
  4. 분석 결과를 CSV 파일로 저장하고 다시 확인할 수 있다.

선수 지식

  • 데이터 프레임의 행과 열을 설명할 수 있습니다.
  • str(), dim(), names()로 데이터 구조를 확인할 수 있습니다.
  • $와 [행, 열]로 값을 선택하고 열을 추가할 수 있습니다.

실제 분석 데이터는 파일에서 시작한다

전사체 분석에서는 다음과 같은 파일을 자주 사용합니다.

  • 샘플 이름과 실험 조건을 기록한 메타데이터
  • 유전자별 발현량을 저장한 행렬
  • 품질 관리 결과를 저장한 표

이 차시에서는 표 형태의 데이터를 저장하는 CSV 파일을 사용합니다.

CSV는 쉼표로 값을 구분하는 텍스트 파일이다

sample_id,condition,cell_count,passed_qc
control_1,control,1200,TRUE
control_2,control,1350,TRUE
treated_1,treated,980,FALSE
  • 첫 줄은 열 이름입니다.
  • 이후 각 줄은 데이터 프레임의 한 행이 됩니다.
  • 일반 텍스트이므로 여러 프로그램에서 열 수 있습니다.

이번 실습의 프로젝트 구조

R 프로그래밍 기초/
├─ data/
│  └─ sample_metadata.csv
├─ labs/
│  └─ 06_data_io.R
└─ results/
   └─ sample_metadata_checked.csv
  • data/에는 원본 예제 데이터를 둡니다.
  • results/에는 코드로 만든 결과를 저장합니다.

작업 폴더는 상대 경로의 출발점이다

getwd()
  • getwd()는 현재 작업 폴더를 보여 줍니다.
  • 이 수업에서는 프로젝트 루트가 작업 폴더라고 가정합니다.
  • RStudio에서 프로젝트를 연 뒤 실습 파일을 실행합니다.

상대 경로는 프로젝트 안의 위치를 나타낸다

input_path <- "data/sample_metadata.csv"
  • 프로젝트 루트에서 data 폴더 안의 파일을 가리킵니다.
  • 다른 컴퓨터에서도 같은 프로젝트 구조를 유지하면 실행할 수 있습니다.
  • Windows에서도 코드 안에서는 /를 사용하면 간단합니다.

절대 경로는 사용자의 컴퓨터에 의존한다

# "C:/Users/name/Desktop/sample_metadata.csv"
  • 절대 경로는 컴퓨터의 특정 위치 전체를 적습니다.
  • 다른 사람의 컴퓨터에서는 같은 위치가 없을 수 있습니다.
  • 재현 가능한 분석을 위해 프로젝트 내부의 상대 경로를 사용합니다.

file.exists()로 파일을 먼저 확인한다

input_path <- "data/sample_metadata.csv"
file.exists(input_path)
  • 파일이 있으면 TRUE, 없으면 FALSE입니다.
  • 불러오기 오류가 발생하면 경로와 파일 이름을 먼저 확인합니다.

read.csv()로 CSV 파일을 불러온다

sample_metadata <- read.csv(input_path)
sample_metadata
  • read.csv()의 결과는 데이터 프레임입니다.
  • 파일의 첫 줄을 기본적으로 열 이름으로 사용합니다.
  • 이번 실습에는 외부 패키지가 필요하지 않습니다.

불러온 직후 일부 행을 확인한다

head(sample_metadata)
tail(sample_metadata)
  • 데이터가 예상한 파일인지 확인합니다.
  • 열이 잘못 나뉘거나 제목 행이 데이터로 들어오지 않았는지 봅니다.
  • 큰 파일은 전체를 출력하기보다 일부부터 확인합니다.

행과 열의 개수를 확인한다

dim(sample_metadata)
nrow(sample_metadata)
ncol(sample_metadata)

예상한 샘플 수와 변수 수가 맞는지 확인합니다.

열 이름을 확인한다

names(sample_metadata)

이번 파일에는 다음 열이 있어야 합니다.

sample_id, condition, batch, cell_count,
median_genes, mito_percent, doublet_rate, passed_qc

str()로 열의 자료형을 확인한다

str(sample_metadata)

확인할 사항:

  • sample_id, condition, batch는 문자형인가?
  • 측정값 열은 숫자형인가?
  • passed_qc는 논리형인가?

summary()로 값의 범위를 확인한다

summary(sample_metadata)
  • 숫자형 열의 최솟값과 최댓값이 예상 범위인지 확인합니다.
  • 논리형 열의 TRUE, FALSE 개수를 확인합니다.
  • 결측값이 있으면 NA's 개수가 표시됩니다.

결측값이 하나라도 있는지 확인한다

anyNA(sample_metadata)
  • 결측값이 하나라도 있으면 TRUE입니다.
  • FALSE라고 해서 모든 값이 생물학적으로 타당하다는 뜻은 아닙니다.

열별 결측값 개수를 확인한다

colSums(is.na(sample_metadata))
  1. is.na()가 각 셀의 결측 여부를 확인합니다.
  2. colSums()가 열마다 TRUE의 개수를 더합니다.
  3. 어느 열에 결측값이 있는지 빠르게 알 수 있습니다.

결측값이 있는 행을 확인한다

incomplete_rows <- !complete.cases(sample_metadata)
sample_metadata[incomplete_rows, ]
  • complete.cases()는 모든 열에 값이 있는 행을 찾습니다.
  • !를 붙이면 결측값이 하나라도 있는 행을 찾습니다.
  • 결측값을 삭제하거나 대체하기 전에 해당 행을 먼저 살펴봅니다.

중복된 샘플 이름을 확인한다

duplicated(sample_metadata$sample_id)
any(duplicated(sample_metadata$sample_id))
  • duplicated()는 앞에서 이미 나온 값을 TRUE로 표시합니다.
  • 샘플 ID는 보통 각 행을 구분해야 하므로 중복 여부를 확인합니다.

범주형 열의 값을 확인한다

unique(sample_metadata$condition)
unique(sample_metadata$batch)
  • unique()는 중복을 제거한 고유한 값을 보여 줍니다.
  • 철자가 다른 값이나 예상하지 못한 범주가 있는지 확인합니다.

숫자형 열을 간단히 점검한다

min(sample_metadata$cell_count)
max(sample_metadata$cell_count)
mean(sample_metadata$cell_count)
  • 값의 범위와 대표값을 확인합니다.
  • 결측값이 있는 열에는 필요할 때 na.rm = TRUE를 사용합니다.
mean(sample_metadata$doublet_rate, na.rm = TRUE)

분석용 열을 추가할 수 있다

sample_metadata$cell_count_k <-
  sample_metadata$cell_count / 1000

head(sample_metadata)

원본 파일 자체를 바꾸지 않고, R에서 불러온 데이터 프레임에 새 열을 추가합니다.

저장할 폴더가 있는지 확인한다

dir.exists("results")
  • 폴더가 있으면 TRUE, 없으면 FALSE입니다.
  • 파일을 저장하기 전에 대상 폴더가 준비되어 있어야 합니다.

dir.create()로 결과 폴더를 만든다

dir.create("results", showWarnings = FALSE)
  • 폴더가 없으면 새로 만듭니다.
  • showWarnings = FALSE는 이미 폴더가 있을 때의 경고를 숨깁니다.
  • 분석 결과와 원본 데이터를 분리할 수 있습니다.

write.csv()로 데이터 프레임을 저장한다

output_path <- "results/sample_metadata_checked.csv"

write.csv(
  sample_metadata,
  output_path,
  row.names = FALSE
)
  • row.names = FALSE는 불필요한 행 번호 열을 저장하지 않습니다.
  • 원본 파일과 다른 경로에 저장하여 원본을 보존합니다.

저장된 파일이 있는지 확인한다

file.exists(output_path)

코드가 오류 없이 끝났더라도 결과 파일이 실제로 생성됐는지 확인합니다.

저장한 파일을 다시 불러온다

saved_metadata <- read.csv(output_path)

head(saved_metadata)
dim(saved_metadata)
str(saved_metadata)
  • 저장 후 다시 불러오는 과정을 읽기 검증이라고 할 수 있습니다.
  • 행 수, 열 수, 열 이름과 자료형이 예상과 같은지 확인합니다.

원본과 저장 결과의 크기를 비교한다

dim(sample_metadata)
dim(saved_metadata)

names(sample_metadata)
names(saved_metadata)

추가한 열을 포함하여 행과 열이 빠짐없이 저장됐는지 확인합니다.

흔한 오류 1: 작업 폴더가 다르다

getwd()
file.exists("data/sample_metadata.csv")

cannot open the connection 오류가 나오면 다음을 확인합니다.

  1. 프로젝트 루트에서 실행했는가?
  2. data 폴더가 있는가?
  3. 파일 이름과 확장자가 정확한가?

흔한 오류 2: 경로의 철자가 다르다

# read.csv("datas/sample_metadata.csv")
  • 실제 폴더 이름은 data입니다.
  • 대소문자, 공백, 확장자 .csv를 모두 확인합니다.

흔한 오류 3: 행 번호가 열로 저장된다

write.csv(
  sample_metadata,
  "results/sample_metadata_checked.csv",
  row.names = FALSE
)

row.names = FALSE를 생략하면 원하지 않는 행 번호 열이 추가될 수 있습니다.

실습 1: 파일 불러오기

input_path <- "data/sample_metadata.csv"
file.exists(input_path)

sample_metadata <- read.csv(input_path)
head(sample_metadata)

파일 경로와 처음 몇 행이 예상한 모습인지 확인합니다.

실습 2: 구조와 이상 여부 점검하기

dim(sample_metadata)
names(sample_metadata)
str(sample_metadata)
summary(sample_metadata)
colSums(is.na(sample_metadata))

결측값이 있는 열과 해당 행을 찾아봅니다.

실습 3: 결과 열 추가하기

sample_metadata$cell_count_k <-
  sample_metadata$cell_count / 1000

head(sample_metadata)

새 열의 값과 자료형을 확인합니다.

실습 4: 저장하고 다시 확인하기

dir.create("results", showWarnings = FALSE)
output_path <- "results/sample_metadata_checked.csv"

write.csv(sample_metadata, output_path, row.names = FALSE)
saved_metadata <- read.csv(output_path)

dim(saved_metadata)
names(saved_metadata)

원본 데이터 프레임과 저장 결과의 크기를 비교합니다.

오늘 배운 내용

  • CSV는 표 형태의 데이터를 저장하는 텍스트 파일입니다.
  • 프로젝트 내부에서는 상대 경로를 사용합니다.
  • read.csv()로 파일을 데이터 프레임으로 불러옵니다.
  • 구조, 자료형, 결측값, 중복값을 불러온 직후 점검합니다.
  • write.csv()로 결과를 저장하고 다시 읽어 검증합니다.
