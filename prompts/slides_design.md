현재 Quarto 프로젝트의 강의 슬라이드 디자인을 전면적으로 개선하라.

## 목표

현재 슬라이드의 내용과 전체적인 장 구성은 유지하되, RevealJS HTML과 PowerPoint PPTX 출력물을 모두 현대적이고 전문적인 대학 강의자료 스타일로 개선한다.

대상은 대학생 및 대학원생을 위한 「R 프로그래밍 기초」 강의자료이다. 지나치게 화려하거나 홍보자료 같은 디자인은 피하고, 가독성·정보 구조·교육적 명확성을 우선한다.

## 먼저 수행할 작업

1. 프로젝트 전체 구조를 확인한다.
2. `_quarto.yml`, 슬라이드용 `.qmd` 파일, 기존 CSS/SCSS, PPTX 템플릿 관련 파일을 조사한다.
3. 현재 RevealJS와 PPTX 렌더링 방식 및 디자인상의 문제를 간단히 분석한다.
4. 기존 파일을 바로 수정하기 전에 변경할 파일과 수정 전략을 제시한다.
5. 분석 후 실제 파일을 수정하고 렌더링 결과를 검증한다.

## 디자인 방향

다음과 같은 현대적인 학술 발표 스타일을 적용한다.

* 미니멀하고 정돈된 레이아웃
* 넓은 여백과 명확한 시각적 계층
* 한 슬라이드에 지나치게 많은 내용을 배치하지 않음
* 제목, 핵심 개념, 설명, 코드, 실습 지시문의 역할이 명확히 구분됨
* 장식보다는 정보 전달 중심
* 일관된 정렬, 간격, 글꼴 크기, 강조 방식 사용
* 밝은 배경을 기본으로 하고 높은 명암 대비 확보
* 접근성과 프로젝터 가독성을 고려
* 모바일 웹 디자인처럼 작은 카드가 지나치게 많이 나열되는 구성은 피함
* 과도한 그림자, 그라데이션, 둥근 모서리, 애니메이션은 사용하지 않음

## 권장 디자인 시스템

### 색상

다음 계열을 기본으로 사용하되, 필요하면 대비를 유지하면서 미세 조정할 수 있다.

* 배경: `#F8FAFC` 또는 흰색
* 기본 텍스트: `#172033`
* 주 강조색: `#2563EB`
* 보조 강조색: `#0F766E`
* 주의 또는 경고: `#B45309`
* 코드 배경: `#F1F5F9`
* 구분선: `#CBD5E1`

강조색은 한 슬라이드에서 과도하게 여러 개 사용하지 않는다.

### 글꼴

가능하면 다음 글꼴 체계를 사용한다.

* 한글 본문과 제목: Pretendard 또는 Pretendard Variable
* 영문 제목 및 강조: Inter
* 코드: JetBrains Mono 또는 Consolas

글꼴이 설치되지 않은 환경에서도 적절한 fallback이 작동하도록 설정한다.

### 타이포그래피

* 슬라이드 제목은 크고 명확하게 표현한다.
* 제목과 본문의 크기 차이를 충분히 둔다.
* 본문 글자가 발표 화면에서 작아지지 않게 한다.
* 긴 문장은 적절히 분리한다.
* 코드 글꼴은 본문보다 약간 작게 하되 읽을 수 있는 크기를 유지한다.
* 한 슬라이드의 텍스트가 너무 많으면 내용을 삭제하지 말고 여러 슬라이드로 분리한다.

## 슬라이드 유형별 디자인

다음 유형을 명확하게 구분한다.

1. 표지 슬라이드

   * 제목 중심
   * 강의명, 차시, 강사 정보는 보조 정보로 배치
   * 불필요한 장식 최소화

2. 장 구분 슬라이드

   * 장 번호와 장 제목을 크게 표시
   * 핵심 학습 목표 또는 한 문장 설명 추가
   * 다른 일반 슬라이드와 시각적으로 구분

3. 학습목표 슬라이드

   * 3~5개의 명확한 학습목표
   * 번호 또는 간결한 구조 사용

4. 개념 설명 슬라이드

   * 핵심 개념을 먼저 제시
   * 설명은 짧은 문단이나 제한된 목록으로 구성
   * 중요한 용어만 강조

5. 코드 설명 슬라이드

   * 코드와 설명의 비율을 적절히 조절
   * 긴 코드는 여러 슬라이드로 나눔
   * 코드 하이라이팅 가독성 개선
   * 실행 결과는 코드와 명확하게 구분

6. 비교 슬라이드

   * 표나 2열 구조를 사용
   * 비교 기준을 명확히 표시
   * 긴 문장을 각 셀에 넣지 않음

7. 실습 슬라이드

   * 실습 목표, 수행 절차, 예상 결과를 구분
   * 학생이 수행해야 하는 행동을 명령형으로 명확히 작성
   * 실습 문제는 시각적으로 구분

8. 요약 슬라이드

   * 핵심 내용 3~5개만 정리
   * 새로운 내용을 추가하지 않음

## RevealJS 수정 요구사항

* 프로젝트 공통 스타일을 관리할 수 있도록 별도의 SCSS 또는 CSS 파일을 구성한다.
* 가능하면 `custom.scss`처럼 의미 있는 파일명을 사용한다.
* 슬라이드별 임시 인라인 스타일은 최소화한다.
* RevealJS의 제목, 본문, 목록, 표, 코드 블록, 인용문, callout, footer, slide number를 일관되게 스타일링한다.
* 코드 블록이 슬라이드 영역을 넘지 않도록 처리한다.
* 긴 표는 글씨만 작게 줄이지 말고 분할을 우선한다.
* `columns`, `incremental`, `fragment` 등 RevealJS 전용 기능은 교육적 필요가 있을 때만 사용한다.
* 불필요한 애니메이션은 제거한다.
* 브라우저 화면과 프로젝터에서 모두 읽기 쉬운지 확인한다.
* 16:9 화면비를 기본으로 한다.

## PPTX 수정 요구사항

RevealJS CSS는 PPTX에 적용되지 않으므로 PPTX 디자인은 별도로 구성한다.

* `reference-doc`로 사용할 PowerPoint 템플릿을 생성하거나 기존 템플릿을 개선한다.
* 슬라이드 마스터와 레이아웃을 활용한다.
* 최소한 다음 레이아웃을 준비한다.

  * Title Slide
  * Section Header
  * Title and Content
  * Two Content
  * Comparison
  * Code / Demonstration
  * Exercise
* HTML과 PPTX가 완전히 동일하게 보일 필요는 없지만, 색상·글꼴·정보 구조는 일관되게 유지한다.
* PPTX에서 텍스트가 화면 밖으로 넘치거나 지나치게 작아지지 않도록 한다.
* Quarto/Pandoc에서 안정적으로 변환되는 Markdown 구조를 우선한다.
* RevealJS에서만 가능한 HTML 구성은 PPTX에서도 의미가 보존되도록 대체 표현을 마련한다.

## 콘텐츠 편집 원칙

* 강의의 핵심 내용, 코드의 의미, 예제의 논리, 학습 순서는 임의로 변경하지 않는다.
* 문장이 지나치게 길거나 중복되는 경우에는 의미를 유지하면서 간결하게 다듬을 수 있다.
* 내용이 많은 슬라이드는 삭제하지 말고 여러 장으로 분리한다.
* 목록 항목은 가능하면 병렬적인 문장 구조를 사용한다.
* 슬라이드 제목은 내용을 구체적으로 나타내도록 개선한다.
* “개요”, “내용”, “예제”처럼 의미가 약한 제목은 구체적인 제목으로 바꾼다.
* 코드가 여러 슬라이드에 나뉘는 경우 문맥이 단절되지 않도록 한다.

## 기술적 제약

* 기존 Quarto 프로젝트의 렌더링 기능을 손상시키지 않는다.
* 상대 경로를 유지한다.
* 이미지와 외부 리소스 경로가 깨지지 않게 한다.
* 불필요한 새 패키지나 복잡한 빌드 도구를 추가하지 않는다.
* 가능하면 Quarto의 표준 기능과 SCSS/CSS, reference PPTX만으로 구현한다.
* 운영체제는 Windows이다.
* 한글 파일명과 공백이 포함된 경로에서도 정상적으로 작동해야 한다.

## 결과물

다음을 완성한다.

1. 개선된 `_quarto.yml`
2. RevealJS용 공통 SCSS 또는 CSS
3. 개선된 `.qmd` 슬라이드 파일
4. PPTX용 reference 문서
5. 필요한 경우 디자인 자산 폴더
6. 변경 사항을 설명하는 `DESIGN_GUIDE.md`
7. HTML과 PPTX 출력 결과

`DESIGN_GUIDE.md`에는 다음 내용을 포함한다.

* 디자인 원칙
* 색상 팔레트
* 글꼴 체계
* 슬라이드 유형별 작성 규칙
* RevealJS와 PPTX의 차이
* 새로운 슬라이드를 추가할 때 따라야 할 규칙
* 렌더링 명령어

## 검증

수정 후 다음을 실제로 실행하여 오류를 확인한다.

```bash
quarto render
```

프로젝트 전체 렌더링이 지원되지 않는 구조라면 개별 `.qmd` 파일을 렌더링한다.

```bash
quarto render 경로/파일명.qmd --to revealjs
quarto render 경로/파일명.qmd --to pptx
```

다음 사항을 검토한다.

* 렌더링 오류가 없는가
* HTML에서 제목과 본문이 겹치지 않는가
* 코드가 화면 밖으로 넘치지 않는가
* 표가 읽을 수 있는 크기인가
* PPTX에서 텍스트가 잘리지 않는가
* 한글 글꼴이 정상적으로 표시되는가
* HTML과 PPTX의 장 제목, 내용, 코드가 누락되지 않았는가
* 슬라이드별 시각적 일관성이 유지되는가

## 작업 방식

우선 프로젝트 파일을 조사한 뒤 다음 형식으로 간단한 진단을 제시한다.

* 현재 디자인의 주요 문제
* 수정할 파일
* 적용할 디자인 시스템
* RevealJS 개선 전략
* PPTX 개선 전략

그 후 실제 파일을 수정한다. 단순히 개선 방법을 설명하는 데 그치지 말고 프로젝트 파일에 변경 사항을 직접 반영한다.
